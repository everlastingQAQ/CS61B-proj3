# DESIGN

## 游戏玩法设计

### 通关条件

地图中有 5 个遗物，获得任意 3 个 -> 出口激活 -> 活着走到出口 -> WIN

### 核心玩法

每次拾取遗物都会激活一种固定怪物。
获得任意 3 个遗物后达到通关要求；剩余两个仍可拾取，会继续激活怪物，并根据遗物类型给予固定 Buff。

### 物品玩法

每种遗物在地图中只出现一次。拾取后立即激活对应怪物；当拾取后的遗物总数大于 3 时，同时获得该遗物对应的 Buff。

| 遗物 | 字符 | 激活怪物 | 第 4、5 次拾取时获得的 Buff |
|---|---:|---|---|
| Crystal | `*` | 猎手 | Vision：视野半径永久 +2 |
| Coin | `$` | 胆小鬼 | Heal：恢复 1 HP，不超过最大 HP |
| Key | `k` | 守卫 | Radar：提示出口方向 |
| Orb | `o` | 伏击者 | Shield：抵挡下一次怪物伤害 |
| Rune | `?` | 巡逻者 | Stun：冻结全部怪物 2 回合 |

### BUFF设置

| Buff | 效果 | 当前状态 |
|---|---|---|
| Vision | 视野半径永久 +2 | 已实现 |
| Shield | 增加 1 层护盾，抵挡一次怪物伤害 | 已实现 |
| Radar | HUD 显示出口八方向 | 已实现 |
| Stun | 冻结全部怪物 2 个行动回合 | 已实现 |
| Heal | 回复 1 HP，不超过最大 HP | 已实现 |

### HUD 信息

所有玩家可见文本统一使用中文；代码内部枚举名继续使用英文，以保持存档兼容。
中文界面统一使用 Fusion Pixel 12px 简体中文比例字体。标题使用 48px 和轻度同色轮廓加粗；菜单、HUD、日志与悬停说明使用 24px 原始字重；字号保持 12 的整数倍并采用最近邻过滤。

1. 顶部左侧显示生命值，中间显示当前生效的护盾、冻结、视野强化和出口雷达，右侧显示遗物进度
2. 怪物类型第一次进入视野时，左下角以单行中文日志显示其名称和行为说明，持续 3 个有效回合
3. “附近”定义为遗物处于玩家当前可见视野内，不再使用固定曼哈顿距离
4. 没有怪物首次提示时，可见遗物会在左下角显示对应怪物与 Buff
5. 鼠标悬停在任意当前可见格子上时，在鼠标附近显示带深色背景的独立说明浮层
6. 悬停内容按实际绘制层级选择：玩家、怪物、物品、场景物件、出口、地形；分别显示生命、行为、Buff、物件效果、出口状态或通行信息
7. 悬停浮层与左下角情境日志相互独立；迷雾格和顶部 HUD 不触发悬停，也不泄露内容
8. 首次见过的怪物类型随存档保存，读档后不会重复提示

### 视野边缘

1. 先以 BFS 计算视野半径内的可见格，墙体会阻断继续扩散
2. 再显示所有与可见透明格八方向相邻的不透明墙体
3. 墙角补全独立于 BFS 半径边界，避免房间拐角被雾层遮掉

### 地图装饰

1. `TileType` 统一声明每种地块的 `walkable` 与 `transparent` 属性，移动、寻路和视野共用该规则
2. 地图拓扑完成并清理墙壁后，由独立的 `DecorationGenerator` 生成装饰
3. 当前随机生成 Grass、Flower、Sand、Moss、Cracked Floor、Mud、Pebbles 七种成片地块，使用椭圆范围与随机缺口避免规则矩形
4. 七种装饰都可通行且透明，只替换普通 Floor，不覆盖墙、连接门或出口，因此不改变地图连通性
5. 装饰使用从世界种子派生的独立随机流；相同种子得到相同装饰，也不会影响玩家、物品和怪物的随机序列
6. 玩家、怪物和遗物均可出现在装饰地块上，装饰类型随世界正常保存和加载

### 功能性场景物件

功能物件使用独立对象层，不写入底层地块，因此不会破坏地图通行性或地面装饰。新地图固定生成下列物件：

| 中文名称 | 字符 | 数量 | 效果 |
|---|---:|---:|---|
| 尖刺陷阱 | `^` | 3 | 玩家踩上去失去 1 HP，可重复触发，不消耗 Shield |
| 治愈泉 | `+` | 1 | 玩家生命未满时恢复 1 HP，随后消失；满血时不消耗 |
| 传送门 | `O` | 2 | 两座传送门双向连接；目标格被怪物占据时不传送 |
| 祝福宝箱 | `B` | 1 | 打开后从现有五种 Buff 中随机获得一种，随后消失 |

1. 物件只生成在可通行地面，不覆盖玩家、遗物和出口，同一格最多一个物件
2. 生成使用从世界种子派生的独立随机流，不改变遗物和怪物的既有随机序列
3. 怪物生成时避开仍然生效的场景物件；场景物件仅由玩家触发
4. 物件类型、坐标、启用状态及传送目标随存档保存；旧存档缺少该字段时按空列表加载

### 数值设置

1. 玩家最大生命值为 3；HP 降到 0 后立即进入 `GAME_OVER`
2. 遗物数量显示为 X/3；4/3、5/3 用红色标记，表示超额
3. 每只怪物接触玩家时造成 1 点伤害
4. 一层 Shield 抵挡一次怪物伤害；同回合的后续怪物仍会继续结算

### 怪物设置

1. 回合制
2. 怪物AI

| 怪物 | 行为 | 实现难度 | 给玩家造成的压力 |
|---|---|---:|---|
| 猎手 | 锁定玩家位置两回合，并通过 BFS 追踪 | ★ | 逼你不断移动 |
| 伏击者 | 预测玩家前方 3 格，并锁定目标两回合 | ★★ | 惩罚一直直线逃跑 |
| 守卫 | 守护 Key 原位置；玩家到守护点路径距离 <= 10 时追击，玩家或怪物到守护点距离 >= 20 时返回 | ★★ | 增加拿遗物风险 |
| 巡逻者 | 在当前连通区域的两个远距离端点之间巡逻 | ★★ | 封锁地图区域 |
| 胆小鬼 | 与玩家路径距离 <= 4 时逃跑，>= 7 时锁定玩家位置两回合追击 | ★★ | 行为难预测 |

3. 每次拾取遗物生成一只对应怪物；优先出生在距玩家曼哈顿距离至少 10 的合法空格
4. 多只怪物同时存在；同一格最多一只怪物，移动冲突由怪物控制器统一处理

### 怪物攻击

1. 怪物尝试进入玩家位置时保持原位，并产生一次接触事件
2. 同回合的接触事件按怪物稳定 ID 顺序逐个结算
3. 有 Shield 时消耗一层 Shield；否则扣除 1 HP
4. HP 最低为 0；归零后立即进入 `GAME_OVER`，停止继续行动
5. 玩家主动进入怪物格时先结算一次接触伤害；存活时双方交换位置，且该怪物本回合不会重复造成接触伤害

### 出口与游戏结束

1. 新游戏在距出生点较远的可达区域旁选择墙格放置关闭出口，不切断原有道路；未激活出口使用橙色 `X`，进入视野后始终显式绘制
2. 拾取第 3 件遗物时出口变为可通行状态
3. 玩家存活并进入已激活出口后进入 `WIN`，不再结算怪物回合
4. 胜利和失败画面支持开始新游戏；按 `M` 或 `Q` 均直接返回主菜单，不关闭程序
5. Radar 激活后在 HUD 显示出口相对玩家的八方向

### Buff 持久化

- Shield 剩余次数随 Player 保存
- Stun 剩余怪物回合数随 Engine 保存
- Radar 激活状态随 Engine 保存
- 出口坐标和激活状态随 GameSave 保存；旧存档缺少出口时自动补建
- 功能性场景物件及其一次性使用状态、传送目标随 GameSave 保存；旧存档缺少时按空列表处理

### 保存后退出

1. 新游戏以及任何成功移动、玩家撞怪或随之发生的交互都会标记为存在未保存进度
2. 保存成功或刚读档后，进度与存档一致；暂停界面按 `Q` 直接返回主菜单
3. 保存后若再次推进有效回合，暂停界面按 `Q` 仍显示保存确认；撞墙和无效按键不产生未保存进度
