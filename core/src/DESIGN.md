# DESIGN

## 游戏玩法设计

### 通关条件

地图中有 5 个遗物，获得任意 3 个 -> 出口激活 -> 活着走到出口 -> WIN

### 核心玩法

每次拾取遗物都会激活一种固定怪物。
获得任意 3 个遗物后达到通关要求；剩余两个仍可拾取，会继续激活怪物，并根据遗物类型给予固定 Buff。

### 物品玩法

每种遗物在地图中只出现一次。拾取后立即激活对应怪物；当拾取后的遗物总数大于 3 时，同时获得该遗物对应的 Buff。

| 遗物 | 字符 | 激活怪物 | 第 4、5 次拾取时获得的 Buff |
|---|---:|---|---|
| Crystal | `*` | Hunter | Vision：视野半径永久 +2 |
| Coin | `$` | Coward | Heal：恢复 1 HP，不超过最大 HP |
| Key | `k` | Guardian | Radar：提示出口方向 |
| Orb | `o` | Ambusher | Shield：抵挡下一次怪物伤害 |
| Rune | `?` | Patroller | Stun：冻结全部怪物 2 回合 |

### BUFF设置

| Buff | 效果 | 当前状态 |
|---|---|---|
| Vision | 视野半径永久 +2 | 已实现 |
| Shield | 增加 1 层护盾，抵挡一次怪物伤害 | 已实现 |
| Radar | HUD 显示出口方向 | 状态与存档已实现，方向提示未实现 |
| Stun | 冻结全部怪物 2 个行动回合 | 已实现 |
| Heal | 回复 1 HP，不超过最大 HP | 已实现 |

### HUD 信息

1. 顶部左侧显示 HP，中间显示当前生效的 Shield、Stun、Vision、Radar，右侧显示遗物进度
2. 怪物类型第一次进入视野时，左下角以单行中文日志显示其名称和行为说明，持续 3 个有效回合
3. 没有怪物首次提示时，玩家靠近遗物 3 格内会在左下角看到遗物对应的怪物与 Buff
4. 首次见过的怪物类型随存档保存，读档后不会重复提示

### 数值设置

1. 玩家最大生命值为 3；HP 降到 0 后应结束游戏（结束状态和画面尚未实现）
2. 遗物数量显示为 X/3；4/3、5/3 用红色标记，表示超额
3. 每只怪物接触玩家时造成 1 点伤害
4. 一层 Shield 抵挡一次怪物伤害；同回合的后续怪物仍会继续结算

### 怪物设置

1. 回合制
2. 怪物AI

| 怪物 | 行为 | 实现难度 | 给玩家造成的压力 |
|---|---|---:|---|
| Hunter | 锁定玩家位置两回合，并通过 BFS 追踪 | ★ | 逼你不断移动 |
| Ambusher | 预测玩家前方 3 格，并锁定目标两回合 | ★★ | 惩罚一直直线逃跑 |
| Guardian | 守护 Key 原位置；玩家到守护点路径距离 <= 10 时追击，玩家或怪物到守护点距离 >= 20 时返回 | ★★ | 增加拿遗物风险 |
| Patroller | 在当前连通区域的两个远距离端点之间巡逻 | ★★ | 封锁地图区域 |
| Coward | 与玩家路径距离 <= 4 时逃跑，>= 7 时锁定玩家位置两回合追击 | ★★ | 行为难预测 |

3. 每次拾取遗物生成一只对应怪物；优先出生在距玩家曼哈顿距离至少 10 的合法空格
4. 多只怪物同时存在；同一格最多一只怪物，移动冲突由怪物控制器统一处理

### 怪物外观

| 怪物 | 字符 | 颜色 RGB |
|---|---:|---|
| Hunter | H | 255, 80, 80 |
| Ambusher | A | 210, 100, 255 |
| Guardian | G | 255, 190, 70 |
| Patroller | P | 80, 180, 255 |
| Coward | C | 120, 230, 120 |

### 怪物攻击

1. 怪物尝试进入玩家位置时保持原位，并产生一次接触事件
2. 同回合的接触事件按怪物稳定 ID 顺序逐个结算
3. 有 Shield 时消耗一层 Shield；否则扣除 1 HP
4. HP 最低为 0；游戏结束状态和画面尚未接入

### Buff 持久化

- Shield 剩余次数随 Player 保存
- Stun 剩余怪物回合数随 Engine 保存
- Radar 激活状态随 Engine 保存
